# iPad R2R deploy toolkit

Maintained source of record for the candidate5 iPad deployment, signing, payload and
PC-witness workflow. The raw experiment evidence remains under
`<EVIDENCE_ROOT>/physical-run5-20261110T0920Z-a1b2c3d4` and is
historical, not generated by this toolkit.

## Files

- `ipad_stage.py` - staged deploy CLI (v5 behavior plus publication cleanup; not byte-identical to the accepted run5 snapshot).
- `ipad_stage_selftest.py` - 92 labelled-fixture checks; no device required.
- `resolve_owner_symbol.py` - offline Mach-O/Lldb symbol resolver; produces owner UUID,
  __TEXT, __TEXT,__managedcode, symbol and file address metadata.
- `pc_capture.py` - LLDB Python adapter that consumes the resolved metadata, waits for
  the actual owner module, computes the load address with the owner __TEXT VM base,
  validates the stopped frame module/UUID and executable memory region, and records the
  actual PC/frame/module/UUID evidence.
- `pc_capture_unit.py` - pure offline arithmetic/gate fixtures, also run by the deploy
  self-test.
- `README.md` - this recipe.

No source/native changes and no signing material are stored here.

## Stage recipe

All commands run on the Mac through Cindy SSH. GUI signing always uses a generated
`.command` opened with `open -a Terminal`; never sign over plain SSH.

1. Whole unsigned asset check:

    python3 "$DEPLOY" --evidence $EV --bundle $BUNDLE --udid $UDID \
      --team $TEAM --identity $IDENTITY \
      bundle-verify --app $UNSIGNED --ready $READY

2. Host signing (new sibling, unsigned input retained):

    python3 "$DEPLOY" --evidence $EV --bundle $BUNDLE --udid $UDID \
      --team $TEAM --identity $IDENTITY \
      sign-plan --app $UNSIGNED --sign-dir $EV/signed-host \
      --profile "$PROFILE" --executable TrustedUpdateHost
    # GUI Terminal completes the sign command
    python3 "$DEPLOY" ... sign-collect --sign-dir $EV/signed-host \
      --app $UNSIGNED --signed-app $SIGNED --executable TrustedUpdateHost --wait 900
    python3 "$DEPLOY" ... sign-verify --signed-app $SIGNED \
      --sign-receipt $EV/signed-host/sign-receipt.json

`sign-verify` checks the profile team, device UDID, expiry, get-task-allow,
application-identifier coverage, actual signed entitlements, Apple Development authority
and the certificate identity fingerprint.

3. Install/update the host once and keep the raw CoreDevice receipt:

    python3 "$DEPLOY" ... install --signed-app $SIGNED \
      --sign-verify-result <latest successful sign-verify result.json>

Do not run the managed compiler/generator before this durable install receipt exists.

4. Fresh post-install A/B owners from source (run only after install):

    python3 "$DEPLOY" ... gen-payload --generator $GENERATOR --version A \
      --sources $SOURCES --host-app $SIGNED \
      --runtime-root $RUNTIME_ROOT --framework-root $FRAMEWORK_ROOT \
      --install-result <install result.json> \
      --sign-verify-result <sign-verify result.json> \
      --run <run-A> --nonce <32hex-A> --output $EV/gen-A
    # same for B with a distinct runId and nonce

`gen-payload` records source before/after hashes, install/sign-verify chronology,
the derived generator receipt and the emitted owner.json. The derived receipt contains
top-level platform 2, rawReceiptPath/rawReceiptSha256, status/installed/signed,
bundleId/deviceUdid/installedUtc/appDigestSha256 and archive links. The finalized native
generator may be given --runtime-root, --framework-root, --dotnet, --csc, --crossgen2,
--device-udid and --bundle-id. The deploy wrapper forwards --device-udid as the native
generator's --udid and forwards --bundle-id directly; the native generator itself uses
--udid, not --device-udid. Any remaining finalized flag can be passed with
--generator-arg. Do not use these against an older generator whose parser does not accept
them.

5. Compose per-version run directories:

    python3 "$DEPLOY" ... compose-payload --payload-root $EV/payload \
      --run-a <run-A> --run-b <run-B> --nonce-a <hex-A> --nonce-b <hex-B> \
      --a-dir $EV/gen-A --b-dir $EV/gen-B \
      --install-receipt-sha256 <sha256 of the derived receipt used by A>

6. Sign external owner dylibs through the same GUI route, collect, reconcile
   payload-files.txt, and seal final signed manifests:

    python3 "$DEPLOY" ... sign-payload --payload-root $EV/payload \
      --signed-payload-root $EV/payload-signed
    # GUI Terminal completes the owner signing
    python3 "$DEPLOY" ... sign-collect-payload --payload-root $EV/payload \
      --signed-payload-root $EV/payload-signed --wait 900
    python3 "$DEPLOY" ... seal-payload --payload-root $EV/payload \
      --signed-payload-root $EV/payload-signed

The sealed manifest keeps raw and signed owner hashes distinct and payload-files.txt is
rewritten with the signed owner digest; the binary payload map excludes payload-files.txt
and payloadFilesSha256 covers the list.

7. Transmit and read back every payload file:

    python3 "$DEPLOY" ... push-payload --payload-root $EV/payload-signed \
      --run <run-A> --nonce <hex-A>
    # same for B

8. Offline actual-owner symbol metadata (no hardcoded offset):

    python3 "$RESOLVER" \
      $EV/payload-signed/<run-A>/TrustedUpdate.A.r2r.dylib \
      --pattern 'Business.*Execute' --lldb-confirm \
      --json-out $EV/pc-address-capture/owner-A.symbol.json

The resolver parses LC_UUID, __TEXT, __TEXT,__managedcode and LC_SYMTAB; it accepts the
Mach-O leading underscore for nm but records the LLDB-visible symbol without it and
optionally confirms the address with LLDB.

9. PC witness. Launch with a background console/start-stopped process and attach with
   LLDB; keep the console session alive. The maintained adapter consumes owner metadata:

    xcrun devicectl device process launch --device $UDID --console --start-stopped \
      --json-output $EV/pc-address-capture/launch-A.json \
      --environment-variables '{"RUNECLR_EXPECTED_VERSION":"A","RUNECLR_GOLDEN_RESULT":"216","RUNECLR_GOLDEN_PRIVATE":"100","RUNECLR_GOLDEN_HELPER":"307"}' \
      $BUNDLE -- --payload <run-A> --nonce <hex-A>

    cd "$DEPLOY_DIR"
    PC_PID=<device result.process.processIdentifier> \
    PC_HOST="$SIGNED/TrustedUpdateHost" PC_OWNER=TrustedUpdate.A.r2r.dylib \
    PC_DEVICE=<PC_DEVICE> \
    PC_METADATA="$EV/pc-address-capture/owner-A.symbol.json" \
    PC_OUT="$EV/pc-address-capture/witness-A.json" \
    lldb --batch -o 'script exec(compile(open("pc_capture.py").read(),"pc_capture.py","exec"), {"__name__": "__main__"})'

`pc_capture.py` stops on shared-library events, matches the owner by exact basename and
optional UUID, then computes `slide = loadBase - __TEXT.vmaddr` and
`expected = symbolVMAddress + slide` from the metadata, or uses the loaded module's own
symbol load address (`GetStartAddress().GetLoadAddress`). It sets an address breakpoint,
records the actual stopped PC/register/frame/module/UUID, and requires the stopped frame's
module basename/UUID to match the selected owner and the actual PC to fall inside a mapped,
readable and executable `SBMemoryRegionInfo` range (base <= pc < end). It does not use a
universal 0x4050 constant.

10. Read the final device result only after normal process completion:

    python3 "$DEPLOY" ... read-result --run <run-A> --nonce <hex-A> --expected-version A

The result must be the exact runeclr.ipados.r2r.result.v1 record (runId, expected/script/
observed version, nonce flags, goldens, contractMvid, resultWriteFailed, ok). A/B
results are fresh processes; the host is not reinstalled after the owners are built.
