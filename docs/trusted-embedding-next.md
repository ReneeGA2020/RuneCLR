## Existing boundaries

- The game supplies its shared CLR contract assembly and host object. RuneCLR
  does not define entity or gameplay methods for this trusted profile.
- Signed staging and recovery remain the authority for selecting the final
  candidate. A generic session is not a substitute for signature verification.
- The existing process gate is occupied before the host activator runs.
  An activation failure or exception does not permit a same-process fallback.
- Trusted R2R modules are noncollectible and remain resident until process
  exit. Closing a logical session does not unload their code or reset statics.

## Small prototype

Start with a host-agnostic session that owns a typed module reference, rather
than moving all of the delivery experiment into a public SDK at once. Its
entry and host interfaces belong to the game's shared assembly. Calls from
the update to the host use ordinary C# interface calls. The host's synchronous
typed invocation callback is borrowed for one call, never stored.

For the first prototype, return primitive values and fixed host-owned failure
codes. Do not expose update exceptions, reflection metadata, delegates or
author instances through diagnostic results. The session may own its module
until close, but a retained closed session must clear that ownership.

Close is idempotent; later calls fail without entering author code. An author
call failure closes the logical session. That policy does not reset the
process's selected version or start another version. Do not add implicit
reflection-based gameplay dispatch or an unload operation. Cleanup callbacks
must have an explicit owner and ordering if the proposal includes them.

In this prototype, `author-failed` means that the borrowed invocation callback
threw a managed exception. It does not identify who caused the failure: a
host callback or a dependency first used by a later call can also throw. The
generic session has no loader policy and does not classify those exceptions.
The initial activation adapter separately preserves existing loader diagnostics
before reporting startup failure. Later invocation failures all close the
logical session without rewriting the receipt or releasing the process gate.
A non-null retained session may already be closed; callers must use IsClosed
or the call result rather than infer usability from a non-null reference.

Keep the prototype and its executable proof outside the production libraries
until its shape has been reviewed. Do not duplicate the accepted manifest
resolver in this ownership experiment. Identify the later integration point
with the existing activator instead.

## Reviewable proof

Use a game-owned contract with no entity API. Demonstrate multiple typed calls,
host reference identity and checked values; then close and reject later calls.
Demonstrate an author exception without retaining its exception object, and
release of an instance-owned host object after close when no module static
retains it. Observe object collection only after the call stack returns;
forced GC is diagnostic, and native context residency is a separate fact.

The report must distinguish a typed-session ownership proof from signed
loading, full manifest resolution, native R2R execution and platform delivery.
Propose the smallest subsequent integration diff, including which existing
signed dependency, activation-gate and native execution checks it must rerun.

| Event | Required result | Receipt and process version |
| --- | --- | --- |
