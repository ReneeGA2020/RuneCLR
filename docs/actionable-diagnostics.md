# Actionable diagnostics

Draft of desktop diagnostics already thrown. This does not close #15. It is not an iOS result.

These checks throw InvalidDataException. Callers distinguish them by message prefix, not by exception type.

| Condition | Message prefix |
| --- | --- |
| Restricted UGC capability denial | Capability profile 'managed-il-gameplay-v1': |
| Dependency metadata identity mismatch | Dependency metadata identity mismatch: |
| Unsupported managed-IL shape, such as P/Invoke or a native entry point | The inspector reason itself, without the capability-profile prefix |

A capability denial is not an identity mismatch, and neither prefix means the package ran. Source-location and symbol mappings are not described here. Full .NET and arbitrary NuGet compatibility are not accepted. Physical iOS was not run.

Package InvalidDataException messages still do not include a source file line. GameplayCapabilityPolicy.cs now includes the IL byte offset for an unsupported, unknown, or truncated opcode and for a truncated operand or switch, for example "IL opcode 'calli' is unsupported at IL offset 0." ManagedAssemblyInspector.cs includes the method name and metadata token, as in "Method '...' token 0x........ uses P/Invoke or InternalCall, unsupported in managed-il-v1.", but not a source line or an IL offset. Symbol mappings remain a #15 gap.

Source compilation is separate. SourceCompiler.ConvertDiagnostic copies Roslyn's diagnostic id, invariant message, severity, and, when the location is in source, the file plus a 1-based line and column into CompilationDiagnostic. It uses GetLineSpan and does not honor an author #line remap. That source path does not add an IL offset to the package inspector exceptions above.

Source compilation emits no PDB, so the package inspector cannot map an IL offset back to a source line. SourceCompiler calls compilation.Emit on the assembly stream only; the call site notes that there is no PDB, disk output, analyzers, or generators. The packaging case "Compiler output is deterministic and contains no PDB" (DeterministicOutput) asserts that the PE debug directory contains neither CodeView nor EmbeddedPortablePdb. Source locations exist only on CompilationDiagnostic. DiagnosticLocations asserts that an author remap #line 700 "invented.cs" is ignored and CS0246 is reported at authors/problem.cs line 4, column 5. ScriptDirectives asserts that #r and #load errors are reported at directives.cs line 1. ConvertDiagnostic uses GetLineSpan and does not honor an author line remap. The inspector does not read a PDB or sequence points. InvalidDataException text still has no source file line. Method rejections include a metadata token, and opcode rejections include an IL offset. This note does not add symbol mapping. Issue 15 stays open. Physical iOS was not run.
